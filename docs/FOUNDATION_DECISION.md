# Решение по основе проекта

**Дата проверки:** 2026-08-14  
**Выбранная база:** Jan `7ccd3c6d32ac7ac97a58d55a94000cb7c883dc6a` (ветка `main`) как десктопная интеграционная база; TurkmenAI Core как самостоятельный слой ценности продукта.

## Итог

Jan признан наиболее подходящей базой для TurkmenAI Local. Его текущее дерево содержит Tauri-слой, веб-интерфейс, модульное `core`, расширения загрузки и `llama.cpp`, аппаратный плагин, локальный server/proxy и CLI. Официальное описание также подтверждает поддержку локальных моделей, Hugging Face, OpenAI-совместимого API и пакетов для Windows, Linux и macOS.[1]

> TurkmenAI Local не является ребрендингом Jan. Он добавляет отдельный слой безопасного разрешения моделей, расчёта совместимости с оборудованием, устойчивой доставки, содержательного хранилища и Turkmen-first реестра.

| Критерий | Jan | Open WebUI | Решение |
|---|---|---|---|
| Нативная десктопная оболочка | Tauri, нативные плагины и lifecycle | Основной фокус — self-hosted веб-платформа | **Jan** |
| Локальный `llama.cpp` runtime | Есть отдельное расширение и orchestration | Ориентируется на внешние runners | **Jan** |
| Аппаратная диагностика | Есть native hardware plugin | Не является основной функцией desktop-клиента | **Jan** |
| Установка и выпуск для desktop | Есть cross-platform build-скрипты, AppImage и Windows packaging | Веб-служба/контейнерный сценарий | **Jan** |
| Серверный браузерный UI для LAN | Возможен как совместимый внешний интерфейс | Сильная сторона проекта | Опциональная будущая интеграция |

## Граница повторного использования

TurkmenAI Local сохраняет upstream отдельно за пределами рабочего build-root в `/home/ubuntu/turkmenai-upstreams/jan-upstream` и фиксирует его ревизию. Изменения к upstream должны поставляться как минимальные проверяемые patch-файлы в `patches/jan/`, а оригинальный код продукта — жить за пределами upstream-дерева. Это сохраняет возможность синхронизации, проверяемую атрибуцию и отсутствие копирования непроверенных частей.

В экспериментальном выпуске `0.1.x` самостоятельный `turkmenai-core` реализует модельные метаданные, анализ безопасности, аппаратное профилирование, планирование запуска, локальное содержательное хранилище, задачи скачивания и API-контракты. Desktop-оболочка использует собственный Tauri shell и может подключать уже установленный runtime; полноценный перенос UI Jan не заявляется как выполненный в этой ревизии.

## Лицензирование

Корневая лицензия Jan — Apache-2.0, что допускает создание производных работ при сохранении соответствующих notices.[2] В `src-tauri/Cargo.toml` конкретный Rust crate объявляет MIT, поэтому перед включением конкретных файлов Jan в TurkmenAI требуется файл-уровневый аудит и сохранение обоих видов уведомлений. По этой причине текущая кодовая база не копирует исходники Jan; она документирует ревизию и использует безопасную process/API-интеграцию там, где это доступно.
